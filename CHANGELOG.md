Version 1.1.0

• Tree v2: the project tree is now the authoritative source of truth for what goes into the dump. Files can be marked Included, Reference-only, or Excluded from the tree itself, and the selection is preserved per project. The filter config no longer decides inclusion at export time; it only shapes the initial state of the tree, and the tree's final state is what the generator iterates.
• Reference-only files: a new third inclusion state lets you list a file in the dump by name and size, without reading its content. Ideal for lockfiles, generated code, and machine-local configuration, all of which were previously either fully included (wasting tokens) or fully excluded (losing structural information the model can use). Configured both by pattern (in the new Reference only section of the dialog) and per file (in the tree). The directory tree header of the dump marks them with a [ref] suffix, and the body emits a [content omitted: N B - reference only] marker instead of the content.
• Per-project tree config: the tree selection is saved to .platform/plugins/com.devdayton.onecodeforai/config.json inside the project, so each project keeps its own decisions independent of the preset. Only the diff between the tree's final states and the filter-derived states is stored, which keeps the file small and stable across filter changes. Only written on Generate; closing the dialog without generating discards manual changes, matching the standard commit-on-generate model.
• Show locked toggle: hard-excluded folders (node_modules, build, .git, ...) and binary files appear as locked nodes in the tree. Enabling "Show locked" makes them interactive. Locking is per-session and safe: unlocking does not automatically include anything inside the folder, so a stray tap on node_modules cannot flood the dump.
• Tri-state checkbox: every row shows its state with a custom tri-state indicator (checkmark for Included, dash for Reference only, empty for Excluded). Cycling a leaf cycles its own state; cycling a folder advances its whole subtree, but only touches descendants whose current state matches the folder's aggregate, preserving manual overrides. Parent and child states stay consistent both ways.
• Aggregate propagation: parent/child state propagation now recurses into the whole non-locked subtree. Previously, cycling a folder only wrote to its direct children, which produced an inconsistent visual state where a folder showed as included while its nested children remained excluded.
• Built-in presets updated: Android, Web, and Python presets now use reference-only entries for R.java, BuildConfig.java, local.properties, package-lock.json, pnpm-lock.yaml, poetry.lock, and Pipfile.lock. The dump stays structurally complete without paying the token cost of those files' contents. The presets also reflect the removal of excludedPaths, which no longer belongs to the profile.
• Tree loading robustness: cancelling a scan, superseding it with a filter change, or hitting an error now always restores the correct panel state. A single treeUiState enum is now the single writer of the tree section's visual state, which prevents orphan "Analyzing..." spinners. The Cancel button and the Reload action both work reliably: Reload expands the section if it was collapsed and re-scans, Cancel returns control to the user with an actionable message.
• Improved initial render: the tri-state indicator and lock glyphs are visible from the first frame, without waiting for a user interaction to trigger a refresh. The row's buildRow method now paints the initial visual state explicitly instead of relying on a later refresh pass.
• Preset spinner no longer restores the last state from SharedPreferences. The preset name and its tree overrides are read from the project's config.json, so the correct preset is always shown for the correct project. Pre-Tree-v2 users who had a last state persisted in SharedPreferences will simply see the Custom preset on first open and can re-select their preferred preset from the spinner.
• FilterConfig: removed the excludedPaths field. Manual per-file decisions are now stored in TreeOverrides, scoped to the project and persisted alongside the tree selection. FilterConfigCodec and PresetManager accept the old excludedPaths key on read and ignore it, so existing profiles load without errors — the affected users just have to re-mark anything they had excluded manually through the tree.
• FilterConfig: added stubPatterns, the rule-based half of the reference-only feature. Uses the same glob syntax as inclusions and exclusions, is evaluated before them in the priority chain, and is persisted alongside them in the profile.
• FileFilter: replaced the boolean include()/includePath() entry points with resolveMode(), which returns a NodeState (INCLUDE, STUB, EXCLUDE) instead of a boolean. The boolean wrappers are kept for backward compatibility, and a new walkIncludedAndStubbed() method returns every selected entry with its state. The filter also exposes hardExcludedDirectories() and binaryExtensions() so the tree scanner can decide which entries become locked.
• CodeDumpGenerator: now receives a Map<String, NodeState> instead of a FileFilter and a config. It writes the full content for INCLUDE entries, a size marker for STUB entries, and nothing for EXCLUDE and LOCKED entries. Progress reporting counts stubs toward the total but not toward bytes, because stubs contribute only a short marker to the output.
• TreeConfigStore: new class that reads and writes the per-project tree config under .platform/plugins/com.devdayton.onecodeforai/config.json. Uses the same JSON codec as the profile preset manager, so the two formats stay interchangeable. Writes are atomic via a .tmp sibling and a rename. Read failures (missing file, malformed JSON, incompatible version) return null and the dialog falls back to the filter-only state.
• TreeOverrides: new data class that holds the per-path manual state changes (includedPaths, stubPaths, excludedPaths). Kept separate from FilterConfig so that the manual decisions are scoped to one project and travel with the config.json rather than with the preset.
• NodeState: new enum with the four states an entry can occupy (INCLUDE, STUB, EXCLUDE, LOCKED). Locked entries are produced only by the scanner and become interactive when the "Show locked" toggle is enabled; they are never persisted.
• PreviewStats: added stubFiles. Stub entries count toward totalFiles but contribute zero to totalBytes and totalTokens, because the dump only writes their header and a short marker. Reporting the source file's real size for a stub would be misleading.
• Settings: added a new tree_show_locked preference that seeds the initial state of the Show locked toggle on each dialog open. Process-wide rather than per-project, because unlocking node_modules is almost always a one-off action and should not persist across projects.
• Strings: added stats_stub_files plural, tree_show_locked, tree_locked_hint, tree_unlock_scanning, section_stub_patterns, no_stub_patterns, add_stub_title, help_stub_title, help_stub_body, help_tree_locked_title, and help_tree_locked_body.
• Drawables: added the four tri-state indicator glyphs (ic_state_include, ic_state_stub, ic_state_exclude, ic_state_locked) and two alternates for the Show locked toggle (ic_tech_lock, ic_tech_eye). The tri-state glyphs share a common checkbox frame so the indicator reads as a single coherent control when cycling.
• Removed the last-state persistence from PresetManager (saveLastState and loadLastState). The information that used to live there is now read from the project's config.json, which has the added benefit of being correctly scoped per project instead of process-wide.
• The default preset list now uses stubPatterns instead of exclusions for lockfiles and generated files. This is a visible change for users who relied on the built-in presets: those files appear in the dump as reference-only entries with their size, rather than being absent entirely. To restore the previous behavior for any specific file, exclude it from the tree directly, or add it to the Exclusions list.
• Nested scroll views in the tree have been renamed to NestedScrollView and WrapHorizontalScrollView to make their role clearer. Their behavior is unchanged.
• Minor: various internal refactors across ProjectTreeView, ConfigurationDialog, and FileFilter to support the new state model. No user-facing changes beyond the ones listed above.
